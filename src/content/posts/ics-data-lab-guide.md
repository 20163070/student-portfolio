## 写前须知

Data Lab 通常会限制你只能使用某些运算符，比如 `~`、`&`、`^`、`|`、`+`、`<<`、`>>`。

所以做题时不要急着写 C 语言里的普通判断，而是先问自己：

1. 这个问题能不能转成二进制规律？
2. 哪些位需要保留？
3. 哪些位需要翻转？
4. 有没有边界情况，比如 `0`、`-1`、`TMin`？

## 代码风格

我比较推荐每道题都先写注释，再写表达式。

```c
/*
 * bitXor - x^y using only ~ and &
 * 思路：
 * 1. x ^ y 表示两位不同则为 1
 * 2. 可以用与、非组合出或运算
 */
int bitXor(int x, int y) {
  return ~(~(x & ~y) & ~(~x & y));
}
```

这样以后回看时不会只看到一串符号，完全忘了自己当时在想什么。

## 测评

每写完一道题，我会做三件事：

- 先用几个小数字手算。
- 再跑官方测试。
- 最后专门想边界情况。

| 类型 | 例子 | 为什么重要 |
| --- | --- | --- |
| 零值 | `0` | 很多位运算在 0 上会暴露问题 |
| 全 1 | `-1` | 补码里经常用于构造 mask |
| 最小值 | `0x80000000` | 取负、右移时容易出错 |

## 辅助工具

我常用这些工具帮助理解：

- `printf`：打印十六进制结果。
- `gdb`：观察中间变量。
- 草稿纸：手写 8 位二进制，比盯着 32 位更容易发现规律。

> [!TIP]
> 如果 32 位太难看清楚，可以先把问题缩小成 4 位或 8 位。小例子跑通后，再推广到 32 位。

## bitXnor

`bitXnor` 可以理解为“相同为 1，不同为 0”。

如果已经知道 XOR 是“不同为 1”，那 XNOR 就是：

```c
~(x ^ y)
```

但如果题目限制不能直接用 `^`，就要先用允许的运算拼出 XOR，再取反。

## bitConditional

这个题的关键是把条件 `x` 变成一个 mask：

- 如果 `x != 0`，mask 应该是全 1。
- 如果 `x == 0`，mask 应该是全 0。

有了 mask 后，就能在 `y` 和 `z` 之间选择：

```c
(mask & y) | (~mask & z)
```

## byteSwap

`byteSwap` 的核心是：

1. 取出第 `n` 个 byte。
2. 取出第 `m` 个 byte。
3. 清空原来的两个位置。
4. 把两个 byte 放回对方的位置。

这个题最容易错在 shift 的单位：题目给的是 byte 编号，但位移要乘以 8。

## logicalShift

算术右移会补符号位，逻辑右移要补 0。

所以做法通常是：

1. 先正常右移。
2. 再构造一个 mask，把左边多出来的 1 清掉。

## 复盘

Data Lab 给我的感觉是：它不是考你背多少 API，而是逼你理解整数在机器里到底怎么表示。

这类 lab 的正确打开方式不是找答案，而是把每道题变成一个小实验。只要你能解释清楚 mask 是怎么来的，这题基本就真的懂了。
